# v0.12.27 Security Hardening Plan

## 1. 目标
下一次安全加固 PR 的目标是在不改变现有产品功能、数据语义、用户流程和已有分享链接兼容性的前提下，降低密码、分享令牌、恢复链路、KV 一致性、CI/CD 供应链和日志观测带来的风险。

原则：安全加固优先；不改成绩事实、不改家庭权限语义、不删除现有分享协议；先测试后切换；任何协议升级必须保留回滚/兼容路径。

## 2. 当前基线
- main: 21d4a3ef99fdceaefc823c70198eaaaa052db845
- version: v0.12.26
- Worker entry: src/v020.js
- Storage: Workers KV
- Password: PBKDF2-SHA256 + random salt + AUTH_PEPPER，当前 20000 iterations
- Secret Share: 32-byte random Bearer Token，KV 保存 token 的 SHA-256 定位值
- Session: HMAC-SHA256 signed token，HttpOnly + Secure + SameSite=Strict
- API/security headers: no-store、CSP、Referrer-Policy 等已存在
- Deploy: GitHub Actions -> Wrangler -> Cloudflare Worker

Cloudflare 当前文档确认 Workers KV 为 eventually consistent，变更在其他全球位置通常可能延迟到 60 秒或更久；需要原子/强一致状态协调时应考虑 Durable Objects。 citeturn790377search1turn790377search10
OWASP 当前密码存储建议：优先 Argon2id；如使用 PBKDF2-HMAC-SHA256，建议 600000 iterations 或以上。生产目标值仍需结合 Worker 基准测试确定。 citeturn790377search0

## 3. 功能冻结边界
本 PR 不改变：
- 考试录入、编辑、删除、恢复。
- 六科、总分、校内排名、班级排名及现有成绩语义。
- 总成绩轨迹、单科对比、时间轴。
- 家庭 owner/editor/viewer 权限。
- 家庭隔离和孩子资料。
- 导出。
- 公开分享与 Secret Share 的用户功能。
- Snapshot / Live 语义。
- 现有字段选择。
- 恢复码和协助恢复流程。

特别约束：现有已生成的 Secret Share 链接在兼容窗口内必须继续可用；本 PR 不一次性切换所有历史分享链接。

## 4. S0：安全资产盘点与历史泄露检查
任务：
- 扫描当前树和 Git 历史中的 SESSION_SECRET、AUTH_PEPPER、ADMIN_BOOTSTRAP_SECRET、CLOUDFLARE_API_TOKEN。
- 扫描 .env、.dev.vars、运行时 Secret 文件、测试 fixture、Playwright artifact。
- 扫描真实测试账号、密码、recovery code、invite token、share token。
- 检查 Actions 日志与错误响应是否可能输出 Secret。
- 建立静态 Secret regression test。
验收：当前树和历史中没有可用生产 Secret；测试只使用假凭据；CI/Worker 日志不出现 Secret 原值。

## 5. S1：密码 KDF 升级与兼容
任务：
- 保留 PBKDF2-SHA256 业务流程。
- 密码记录明确 version、algorithm、iterations、salt、hash。
- 以 OWASP 600000 iterations 作为参考起点，先做 Cloudflare Worker 实测 benchmark。
- 新建账号使用新参数。
- 旧账号登录成功后执行 lazy rehash，不要求用户主动改密码。
- 密码重置、邀请注册、家庭成员创建统一走同一密码策略。
禁止：password 进入 KV 明文、URL、日志、返回 JSON 或浏览器持久化存储。
验收：新旧账号均可登录；旧 hash 能升级；错误密码不改 hash；登录性能经过生产环境级 benchmark。

## 6. S2：Secret domain separation
建议逐步拆分：
- PASSWORD_PEPPER：仅密码。
- TOKEN_PEPPER：邀请、恢复、分享 locator。
- SESSION_SECRET：仅 Session 签名。
- ADMIN_BOOTSTRAP_SECRET：仅管理员建户。
兼容：新增 record version；旧 Token 按旧规则继续验证至自然失效；新 Token 统一使用新域。
验收：单一 Secret 泄露不会直接横向破坏其他密码学域。

## 7. S3：Share Token 安全收口
第一阶段保持旧分享协议：
- 保留旧 Secret Share 链接。
- 应用日志禁止输出原始 token。
- 错误追踪只允许 hash 或截断 locator。
- 不把 token 写入 analytics、telemetry、DOM debug、localStorage、sessionStorage。
- 分享页面继续 no-store、no-referrer。
- 检查未来接入的监控/错误平台不能采集完整 URL。

第二阶段为新 Share 预留 E2EE v3：
- 形式：/share/<share-id>#<client-key>。
- share-id 服务端可见；client-key 只在浏览器 Fragment。
- Worker 只保存/返回密文，浏览器使用 Web Crypto 本地解密。
- 初版 AES-GCM。
- 加密包必须版本化并包含 algorithm、iv、salt、ciphertext 等必要元数据。
- 历史 /share/<secret-token> 保留兼容窗口。

本 PR 不要求一次性完成 E2EE 全量迁移；只完成安全收口和迁移设计/回归基础。

## 8. S4：一次性邀请与恢复链路的并发安全
当前 KV 不适合严格的一次性消费状态机。Cloudflare 文档明确指出 KV eventually consistent，且 concurrent writes to same key 可能互相覆盖；需要强一致时可考虑 Durable Objects。 citeturn790377search1turn790377search10
任务：
- 评估仅为 invite consume、recovery link consume、必要的 session security state 引入小型 Durable Object。
- 成绩数据继续保留在 KV。
- 不把整个项目迁移到 Durable Objects。
验收：并发 accept 只能成功一次；并发 recovery reset 只能成功一次；密码重置后旧 Session 失效；撤销/过期语义保持不变。

## 9. S5：敏感接口抗滥用
覆盖：
- /api/login
- /api/recovery/code
- /api/recovery/reset/*
- /api/invitations/*/accept
- /api/admin/provision
原则：正常用户流程不变；按账号/IP/Token 生命周期做轻量限速；统一错误表现，避免账号枚举；不记录密码和 Token。

## 10. S6：CI/CD 供应链
任务：
- GitHub Actions 使用 immutable commit SHA。
- Wrangler 使用明确固定版本，不使用不可控 latest。
- npm 继续严格依赖 package-lock。
- Deploy 继续只部署经过 CI 的 exact SHA。
- Cloudflare API Token 最小权限。
- 保留 production appVersion + buildSha attestation。
验收：PR tested SHA、部署 checkout SHA、production buildSha 三者一致；Deploy Secret 不进入日志；非 main CI 不触发生产部署。

## 11. S7：生产观测隐私
全面审计 Worker Logs、Actions Logs、browser console、error responses、Playwright artifacts。
敏感字段包括：password、authorization、cookie、score_session、share token、recoveryCode、invite token、学生成绩对象。
日志只允许记录 route、status、latency、hash/truncated identifier 等最小信息。

## 12. 测试矩阵
单元：KDF、lazy rehash、constant-time compare、token hash、domain separation、Share projection、E2EE envelope、ciphertext/key errors。
API：未登录、跨家庭、viewer 写操作、CSRF、Origin、expired/revoked share、recovery reuse、invite reuse、旧 Session 失效。
并发：double invite accept、double recovery reset、concurrent password reset、share revoke/create。
浏览器：Chromium + WebKit，desktop + mobile；登录、录入、编辑、分享、复制、撤销、历史分享兼容。
若进入 E2EE 迁移验证，必须检查 Fragment 不出现在 HTTP Request URL 中。

## 13. 发布红线
- 不能让旧分享链接失效。
- 不能改变成绩数据或成绩计算语义。
- 不能突破家庭隔离。
- 不能让 viewer 获得写权限。
- 不能在日志里出现 Secret。
- 不能出现 invite/recovery 双消费。
- 不能出现 tested SHA 与 production buildSha 不一致。
- 版本必须同步到 v0.12.27。

v0.12.27：
- S0 安全资产与历史泄露检查。
- S1 密码 KDF 升级 + lazy rehash。

- S3 旧 Share 兼容前提下的 Token/日志收口。
- S5 rate limiting。
- S6 CI/CD supply-chain hardening。
