# Deployment source-of-truth correction / v0.12.29.10

## Baseline
- Main SHA: d8c6e3c6c7cbcc30f260e650b5be1f78bcf9974f
- v0.12.29.9 CI passed, but production deployment attestation failed.
- Deployment log proved `--keep-vars` left production APP_VERSION at 0.12.29.7 despite the repository value being 0.12.29.9 and an explicit CLI `--var APP_VERSION` attempt.

## Decision
The repository's `wrangler.toml` is the release source of truth for non-secret Worker variables. Remove `--keep-vars` from the deploy command. Keep `--secrets-file` because secrets are managed separately, and keep the explicit BUILD_SHA injection.

## Implementation
1. Remove `--keep-vars` and the redundant APP_VERSION CLI override.
2. Keep production attestation on both expected appVersion and exact buildSha.
3. Strengthen deploy workflow contract tests so `--keep-vars` cannot return silently.
4. Bump release to v0.12.29.10 and sync package, lockfile, Worker config, changelog and release assertions.
5. Full CI, merge, then production deployment verification.

## Acceptance
- CI verify + Chromium/WebKit share browser tests: success.
- Production deploy output uses APP_VERSION 0.12.29.10 from the tested commit.
- /api/health returns appVersion 0.12.29.10 and buildSha equal to the exact tested main SHA.
