# Exact production version attestation / v0.12.29.12

## Baseline
- Main SHA: ea325c98ae7f461cb4419720387974cfebb395d7
- v0.12.29.11 deploy successfully created APP_VERSION 0.12.29.11, but the production verification immediately after deploy could still hit the previous 0.12.29.7 version before traffic propagation completed.
- CI passed; deploy failed only at the second production verification step.

## Root cause
The deployment verifier performs an unpinned public request. Cloudflare can briefly serve a previous Worker version while a newly deployed version propagates. Cloudflare documents version overrides as the mechanism for testing a specific deployed Worker version.

## Fix
1. Capture the exact `Current Version ID` emitted by `wrangler deploy`.
2. Pass that version ID into production attestation.
3. Send `Cloudflare-Workers-Version-Overrides: score-track="<version-id>"` on health and asset verification requests.
4. Keep a short retry window for propagation before failing.
5. Add tests for the version-override header and deployment version-id capture.
6. Bump release to v0.12.29.12 and sync package/lock/wrangler/changelog/assertions.

## Acceptance
- CI verify + Chromium/WebKit share-browser pass.
- Deploy log captures a version ID.
- Production health and asset verification are pinned to that exact version.
- /api/health returns appVersion 0.12.29.12 and exact tested main SHA.
- Final main and production verification both reference the same exact SHA/version.
