# Deployment APP_VERSION contract / v0.12.29.9

## Baseline
- Base main SHA: e78de6cd8f55b686e2312b9c14e11119cb8b7275
- Main release: v0.12.29.8
- Production deployment run exposed a deployment-contract defect: `wrangler deploy --keep-vars` preserved the existing Cloudflare APP_VERSION (0.12.29.7), so production attestation failed even though the tested commit contained v0.12.29.8.

## Fix
1. Keep `--keep-vars` for existing dashboard-managed variables.
2. Explicitly pass `--var APP_VERSION:${EXPECTED_VERSION}` during deployment so the release version from the tested commit wins over the stale persisted value.
3. Add a workflow contract test preventing regression.
4. Bump release to v0.12.29.9 because this is a new revision; sync package, lockfile, Worker config, changelog and release assertions.
5. Re-run full CI, then exact-SHA production deployment attestation.

## Acceptance
- CI verify: success.
- Share browser tests: Chromium + WebKit success.
- Deployment output exposes APP_VERSION 0.12.29.9.
- Production `/api/health` attests appVersion 0.12.29.9 and buildSha equal to the exact tested main SHA.
- No Schema/KV/API migration.
