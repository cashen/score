# 高三坐标（Score）

> 看见现在的位置，也看见一路的变化。

家庭用的高三考试轨迹工具：记录语文、数学、英语、物理、化学、生物的成绩与班级/学校排名，更强调“相对位置变化”，而不是把不同难度试卷的绝对分数机械横比。

产品回答问题的顺序固定为：

> 孩子现在在哪 → 最近有没有变化 → 变化来自哪一科 → 再回到具体考试和分数核对

## 技术基线

- Cloudflare Worker + Static Assets
- Workers KV（不使用 R2 / D1）
- GitHub 只保存源码，不保存孩子成绩
- 原生 HTML/CSS/JS，无第三方前端 SDK
- 一个家庭可以容纳多个成员/多个孩子的数据模型

## 分析边界

高三坐标不会把一次考试的分数变化直接包装成“能力提高/下降”。趋势首先要求考试类别一致：

- 月考只和月考比较；
- 联考和校考可以作为同一类别观察；
- 一模、二模、三模统一按模考类别观察；
- 其他考试默认只与自身同类别比较。

单科历史仍然展示所有考试。类别规则只决定哪些考试进入趋势判断，不会把其他历史记录隐藏掉。

在类别一致的前提下，分析优先级是：

1. 学校百分位；
2. 学校排名；
3. 班级排名；
4. 只有在缺少相对位置时，才把分数作为辅助观察。

联考位次用于描述联考范围内的位置。联考与校考合并观察时，只使用两类考试共有且口径一致的学校/班级位置；不会把“联考位次”和“校排名”当成同一个数字做趋势运算。

如果不同考试的口径或难度不可确认，页面会明确提示可比性限制。产品不预测高考分数、录取结果，也不使用制造焦虑的“严重退步/必须干预”文案。

## 为什么现在用 KV

当前项目目标是不依赖信用卡/计费验证，并且用户现有 D1 免费额度已被其他业务占用。成绩记录是典型低频写入：一次考试通常只发生创建和少量补录。KV 的最终一致性边界被显式保留在架构中，不把它伪装成事务数据库。

## Cloudflare 部署

见 `docs/DEPLOYMENT.md`。必须先创建一个 Workers KV namespace，并设置三个 Worker Secrets：

- `SESSION_SECRET`
- `AUTH_PEPPER`
- `ADMIN_BOOTSTRAP_SECRET`

这些 Secret **不能**提交到 GitHub。

## 数据隐私

默认状态是 Private。Public 并不等于 Searchable：即使家庭主动创建公开主页，也会返回 `noindex, nofollow, noarchive`，不会提供公开学生目录、搜索或排行榜。
