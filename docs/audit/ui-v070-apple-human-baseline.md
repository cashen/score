# v0.7.0 高三坐标 UI 基线审计

## 审计范围

本次只审视高三坐标的家庭端 UI 与交互，不重写数据模型、KV 存储、鉴权、分享白名单或考试可比算法。

基线：`main` 最新提交 `03e86273d0af709b25e9a883d16dd4ea7c2527b8`，应用版本 `0.6.0`。

## 已有能力（必须保留）

- 首页已按“身份 → 当前坐标 → 可比变化 → 六科 → 完整轨迹”组织。
- 成绩录入已有三步结构、分步保存提示和本机草稿恢复。
- 删除可恢复、考试类别有可比边界、分享默认单次且支持撤销。
- 生产入口使用原生 HTML/CSS/JS，不引入新的前端 SDK。
- 移动端已保留考试坐标与触摸目标，不得通过视觉重构隐藏信息。

## 人类体验问题

1. 首页虽然有正确的信息顺序，但当前首屏主动作不够明确；有数据时用户首先看到“编辑这次考试”，而不是自然的“记录下一次考试”。
2. 顶部导航与内容同样抢占注意力，家庭隐私状态不够显眼但也不应做成警报。
3. 变化区容易被读成机械指标，需要把“事实、比较口径、下一步”分层。
4. 轨迹入口是折叠详情，缺少明确的可发现性和稳定的锚点行为。
5. 旧样式的卡片、边框和阴影叠加后，在手机上会产生“数据面板”感，不像低频家庭工具。
6. 部分交互反馈仍依赖通用按钮样式，缺少按下即反馈、可中断和减少动态模式的统一约束。

## 不做的事情

- 不增加 AI 对话、录取预测、排行榜、徽章或社交流。
- 不把示例性的“进步”包装成能力结论。
- 不把不同考试口径强行画成连续趋势。
- 不引入玻璃拟态、全屏动效、复杂图表或新的存储依赖。

## 验收原则

- 首次进入、录入、查看变化、纠错、分享五个任务均有明确主路径。
- 3 秒内能理解当前孩子、最近考试、当前坐标和下一步动作。
- 任何新视觉层都不能破坏 v0.6 的数据字段、权限和可比性文案。
- 手机宽度 360px、桌面、键盘操作、增大字体、减少动态均可用。
