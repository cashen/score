# v0.12.29.5 Production deployment contract repair

## Finding

The first production deployment attempt after PR #57 was rejected by Wrangler 4.135.0 before deployment because the observability configuration declared `invocation_logs = false` without an explicit `observability.logs.enabled` or top-level observability enabled state.

This is a deployment-contract defect, not an application-runtime defect.

## Scope

1. Make observability logging explicitly disabled in a Wrangler 4.135-compatible form:
   - `[observability.logs]`
   - `enabled = false`
   - `invocation_logs = false`
2. Add a source contract test that requires the explicit disabled state and prevents future drift.
3. Bump package, lockfile and Worker APP_VERSION together to v0.12.29.5.
4. Record the production deployment repair in CHANGELOG and this plan.
5. Re-run `npm verify` and the full Chromium/WebKit browser suite.
6. Merge only the exact green PR head.
7. Verify the main merge SHA and observe the production deployment workflow to its final health-attestation result.

## Non-goals

- No business-logic changes.
- No Schema 2 or KV migration.
- No authentication/share changes.
- No re-enable of Worker invocation logs.

## Merge gate

Exact tested PR head must be merged. Production is not considered complete until the deployment workflow's own `/api/health` version/build SHA attestation succeeds.
