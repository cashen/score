# v0.10.0 坐标判断层：变化归因与下一次观察点

## 目标
把已有的成绩事实、相对位置和可比考试能力，收敛为一个低干扰的“坐标判断层”：10 秒内回答“现在在哪、最近怎么变、变化主要来自哪科、下一次最值得观察什么”。

## 产品边界
- 只做事实归纳与观察提示，不预测高考分数、录取结果或能力。
- 优先使用可比较的学校百分位；其次学校排名、班级排名，最后才用分数作为辅助。
- 不可比、缺失、缺考和只有一场考试时，不制造趋势结论。
- “下一次观察点”只描述值得继续核对的对象，不给出教学处方。
- 不改变 KV、认证、分享白名单、Schema 1、API 与现有比较规则。

## 分阶段
### S0 基线
- 基于 main `5854d0482c7ca85cd497b3e48bc6cbf86fee6a52`。
- 创建独立分支与本计划。

### S1 分析核心
新增 `public/coordinate-insight-v100.js`，纯函数输出：
- current：最新考试的当前位置摘要；
- comparison：最新与最近可比考试的变化；
- drivers：六科变化排序与方向；
- attention：下一次值得继续观察的科目；
- boundary：基线/不可比/数据不足说明。
分析层不得读取 DOM、localStorage 或修改数据。

### S2 私有首页接入
通过 router 在私有应用启动后加载分析层；分析层基于当前学生 API 数据建立判断卡片。保留现有首页“六科/完整轨迹/考试”操作，不替换现有事实展示。

### S3 人话与可访问性
- 首屏只增加一块“坐标判断”，避免再增加导航层级。
- 所有结论可由当前展示的数据复核。
- 使用中性色与小面积强调，不以红绿表达成绩好坏。
- 触控目标不低于 44px；键盘可访问。

### S4 测试
- 纯函数覆盖：0/1/2/3+ 场考试；类别不同；系列不同；层级不同；排名有/无人数；分数回退；缺科；特殊考试。
- 浏览器覆盖：空数据、单场基线、多场可比、多场含不可比记录、学生切换。
- 不影响分享页、登录/引导、家庭管理和现有时间轴。

### S5 版本与交付
- package / lock / wrangler / CHANGELOG 升至 `0.10.0`。
- `npm ci && npm run verify` 通过。
- PR exact head CI 通过后合并。
- 合并后验证 main CI、Cloudflare 部署、`/api/health` 的 appVersion/buildSha/schema/storage，以及首页资源。

## 回滚
纯前端分析能力，无 KV migration。若出现问题，删除 router 加载点与新增分析模块即可回到 v0.9.4；数据合同不变。
