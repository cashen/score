# 高三坐标 Human Data Semantics / Reading Continuity — v0.12.0

## 0. 基线与目标

当前代码基线：

- repository: `cashen/score`
- main SHA: `d1d27877e187e2c9a4583c6125625fe13975e49b`
- runtime version: `0.11.0`
- schemaVersion: `1`
- storage: `workers-kv`

本计划不是继续针对某一个页面打补丁，而是一次性解决一条完整事实链：

`编辑页录入 → 成绩存储 → 综合/时间轴读取 → 单科比较 → 分享页投影`

> 用户在哪个页面编辑、查看或分享“这一次考试/这一个科目/这一个位置”，系统就必须解释成同一个事实对象，并明确区分“没有数据”“没有这项”“没有分享”“暂时不能比较”。

本版本特别把**编辑页作为事实源头**纳入范围：校位次、班级位次、总分位次、参考人数、六科成绩/排名、官方总分等字段均按独立事实处理；编辑页不得通过默认值、历史回填或指标互换制造新事实，保存后也不得改变用户正在看的考试/科目/指标上下文。

目标是建立统一的：

`考试事实 → 最近一次 → 科目事实 → 排名事实 → 比较事实 → 页面状态 → URL状态`

行为链。

# 1. 已确认的问题

## 1.1 单科默认值不符合人的意图

“单科”无 `subject` 时不应默认语文。

当前产品应为：

`单科 → 六科概览 → 当前科目焦点`

而不是：

`单科 → 默认语文`

“英语”表示当前阅读焦点，不意味着其他科目被过滤或不存在。

---

## 1.2 单科有历史记录，却没有优先告诉用户“发生了什么”

当前单科页可以列出：

- 9月月考
- 8月月考
- 7月月考

但没有把“最近一次可比变化”作为首要阅读结果。

目标：

- 只有一次：展示“当前基线”
- 有两次以上可比：首先展示最近一次变化
- 有历史但无法比较：说明原因，不硬下结论
- 再向下展示完整历史

阅读顺序应为：

`当前值 → 最近一次可比变化 → 完整历史`

---

## 1.3 单科的排名信息没有进入默认比较结果

当前单科存在：

- 分数
- 学校排名
- 班级排名

但默认状态仍然偏向单纯列分数。

应复用已有 `metricBetween()` / trajectory core 的优先级，采用：

1. 可可靠比较的学校相对位置（percentile）
2. 学校排名
3. 班级排名
4. 分数

并遵守：

- 排名口径一致才能做排名变化
- 只有参与人数完整时才能计算 percentile
- 没有可靠排名时才退回分数
- 页面文案必须与实际采用的指标完全一致

---

## 1.4 综合、单科、时间轴的排名展示规则没有完全统一

目标规则：

### 综合

回答：

> 最近一次考试整体怎么样？

显示：

- 总分/六科合计/部分小计
- 学校排名
- 班级排名
- 最近一次可比考试变化

### 时间轴

回答：

> 每一次考试整体发生了什么？

每个节点显示：

- 考试名称
- 日期
- 类型
- 整体总分/六科合计/小计
- 整体学校排名
- 整体班级排名

打开节点后再显示该场具体六科事实。

### 单科

回答：

> 这门课最近怎么样？

显示：

- 当前科目最近一次成绩
- 当前科目最近一次有效排名
- 最近一次可比变化
- 完整历史

不要把六科全部塞进单科页，也不要让单科变成纯分数列表。

# 2. “最近一次”必须有明确语义

当前 `latestExam()` 使用 `state.exams[0]`，而服务端 `loadExamIndex()` / `saveExamIndex()` 按：

`date DESC → updatedAt DESC`

排序。

必须正式定义：

> “最近一次考试”按考试日期，而不是最后编辑时间。

因此发现一个当前未被用户直接提出、但必须修的隐性问题：

如果两场考试日期相同，后编辑的旧考试可能因为 `updatedAt` 改变而跑到列表前面。

实施规则：

1. 主排序键：`date DESC`
2. 同日次序：使用稳定字段（优先 `createdAt DESC`）
3. 不能因为编辑旧记录而改变“哪场是最近一次”
4. “最新”标签与所有视图必须共用同一排序函数

同时禁止在不同页面自己写不同的“最新”算法。

---

# 3. 最新考试不等于最新完整考试

必须锁定一个非常重要的行为：

> “最近一次”始终是最近一次考试，不得因为数据不完整而静默跳回更早的完整考试。

例如：

- 9月月考：最新，但只录了 4 科
- 8月月考：完整 6 科

首页仍然必须显示：

`9月月考`

不能偷偷把 8 月作为“最近一次总成绩”。

显示：

- 总分若存在 → 显示
- 官方总分不存在但可完整计算 → 显示六科合计
- 只有部分科 → 显示“已录 x/6 科”
- 整体排名有 → 显示
- 没有 → 留空/不显示

这一规则要写进测试，避免以后出现“看起来更完整，所以系统擅自跳历史”的行为。

---

# 4. 编辑页必须成为统一事实语义的第一道门

编辑页不是本次分享页之外的另一个范围，而是所有展示语义的事实源头。必须逐字段验证并保持以下边界：

- 总分、总分位次、学校位次、班级位次彼此独立；不能互相回填。
- 各科成绩、各科排名、各科参考人数彼此独立；不能用上一场数据补当前场。
- `rank` 存在但 `participants` 不存在时，只保留排名，不生成百分位。
- `participants` 存在但 `rank` 不存在时，不生成排名。
- 分数与排名可以单独存在，保存时不能因为另一字段为空而删除已有事实。
- `finalScore`、`rawScore` 都必须受满分约束；编辑页校验规则必须与服务端模型一致。
- 用户留空的字段保存后仍保持留空；重新打开编辑页时不能出现系统猜测的历史值。
- 编辑后必须返回原 `tab / view / subject / metric / exam` 上下文，而不是因为保存动作跳到默认页面。

建议在 UI 层明确区分“输入为空”和“输入为 0”，但本版本不引入新的 Schema 迁移；空值仍按现有 Schema 1 兼容策略处理。

---

# 5. 科目数据必须区分“没有数值”和“没有这项事实”

当前 `normalizeExam()` 为六个科目都建立对象，因此前端看到的“空对象”不能自动理解成：

- 没考
- 没录
- 没排名

第一阶段采用安全策略：

### 读页面

如果成绩没有、排名也没有：

- 不输出“—”
- 不输出“排名待补”
- 不把空科目当成有效数据展示

### 编辑页面

继续允许用户把不知道的数据留空，并明确提示：

> 不知道的数据可以留空。

### 不做猜测

旧数据没有“本场是否实际参加该科”的显式信息时，不从空对象反推“没考”。

如果未来确实需要严格区分：

- `recorded`
- `not_recorded`
- `not_applicable`

再引入显式 subject presence 状态；本版本优先保证不制造虚假的成绩/排名。

---

# 6. “空值”必须统一语义

禁止一个 `—` 同时表示：

- 未记录
- 不适用
- 未分享
- 无法比较

统一规则：

### 有值

直接显示事实。

### 未记录

读页面尽量留空；编辑页面可以提示“未记录”。

### 未分享

公开分享页面明确显示：

`未分享`

### 无法比较

显示原因，例如：

- 考试类别不同
- 考试系列不同
- 考试范围不同
- 当前/参考考试有特殊情况
- 当前科目缺数据
- 排名口径不一致

绝不能把“无法比较”显示成“下降/上升”。

---

# 7. 最近一次可比考试：必须是“考试可比 + 当前科目可比”

已有 trajectory core 已经提供：

- `comparisonEligibility()`
- `findComparableExam()`
- `comparableSet()`

必须统一复用。

但当前单科还缺一层：

> 找到“考试级可比”的上一场之后，还要检查当前科目是否有足够数据。

例如：

- 9月月考 vs 8月月考：考试类型/范围一致
- 但 9月英语没有成绩

此时不能说“英语下降”。

应进入：

`历史存在，但本次英语没有可比较数据`

状态。

---

# 8. 单科默认比较应该是“自动”，不是强迫用户理解指标

当前单科有：

- 分数
- 学校排名
- 班级排名

但默认不应该一进页面就让用户做判断。

建议内部增加：

`subjectMetric = auto`

自动选择：

1. 学校相对位置
2. 学校排名
3. 班级排名
4. 分数

用户仍然可以主动切换：

- 分数
- 学校排名
- 班级排名

但“自动”承担默认值。

URL：

`view=subject&subject=english`

默认采用 `auto`。

如果用户明确选择学校排名：

`view=subject&subject=english&metric=schoolRank`

则必须保持该选择。

---

# 9. 单科页面必须补“最近变化摘要”

建议目标结构：

## 英语

### 最近一次

`134 分`

`校第 38 名 · 班第 5 名`

### 和上一场可比英语相比

例如：

`校前 18.2% → 校前 14.7%`

`学校相对位置向前 3.5 个百分点`

下面注明：

`比较对象：8月月考`

再下面：

`英语的历次记录`

- 9月月考
- 8月月考
- 7月月考

这样先回答“发生了什么”，再给完整历史。

---

# 10. 单科没有可比记录时也要有清晰状态

不能只显示一句：

`先记录更多同类别考试`

应该根据实际状态区分：

### 只有一次

`当前基线`

### 有多次，但考试不可比

`已有历史记录，但最近考试与之前记录的比较口径不同，暂不直接比较。`

### 考试可比，但科目缺数据

`两场考试可以比较，但当前科目缺少足够数据，暂不判断变化。`

### 排名无法比较，但分数可比

如果产品策略允许，则明确：

`学校排名口径不同，本次先比较分数。`

禁止系统把“自动 fallback”隐藏起来。

---

# 11. 综合“总成绩”必须明确是最近一场

综合页顶部明确建立上下文：

`最近一次：9月月考 · 2026-09-xx`

下面是：

- 官方总分
- 六科合计
- 部分小计
- 整体学校排名
- 整体班级排名

如果总分或排名缺失：

- 空值留空
- 不回退到旧考试
- 不把旧考试数据拼到最新考试上

---

# 12. 时间轴的职责：节点，不是分析仪表盘

时间轴继续简洁：

`9月月考 · 校第38 · 班第6 · 610分`

`8月月考 · 校第45 · 班第8 · 605分`

点开以后再看：

- 本场整体
- 六科成绩
- 六科排名
- 本场比较对象

不要把六科趋势和复杂分析全部塞进时间轴主列表。

同时修复当前历史详情比较对象逻辑：

> 当前页面必须寻找“这场考试之前最近的可比考试”，不能简单寻找第一场不同考试。

这一点 v0.11.0 已修复，但必须正式纳入回归测试。

---

# 13. 公开分享和私有页面必须遵守同一事实模型

现在 public/private 两套渲染仍存在不同程度的实现差异。

本版本规定：

`事实模型`

必须共用，包括**编辑页写入后的事实回读**：

- 最近考试定义
- subject 数据是否存在
- ranking 展示规则
- comparison eligibility
- auto metric
- missing/unshared semantics

公开页面只是因为白名单而少字段，不允许重新发明一套事实。

---

# 14. 分享页面的特殊要求

公开分享继续遵守：

- Share v2 runtime
- single share 固定 examId
- trajectory live 可持续更新
- snapshot 不吸收未来考试
- whitelist 控制字段
- 未分享字段显示“未分享”

单科分享：

- 单科仍支持六科概览
- 直接 deep link 指定科目
- 有历史则显示该科历史
- 有可比历史则显示该科变化
- 没有排名但有分数则只讲分数

# 16. 指标计算和页面文字必须完全同源

任何一个变化结论都必须携带：

- metric
- current value
- previous value
- delta
- comparison reference

渲染器不能自己猜 metric。

例如：

`metric = score`

只能说：

`分数高 6 分`

不能说：

`整体位置向前`

例如：

`metric = schoolRank`

显示：

`学校排名第 x → 第 y`

例如：

`metric = percentile`

显示：

`学校相对位置向前 x 个百分点`

目标：

> 计算层输出事实，展示层只负责把事实说成人话。

---

# 17. 排名显示规则

## 16.1 有 rank + participants

可显示：

`校第38名 / 900人`

以及 percentile。

## 16.2 只有 rank

可显示：

`校第38名`

但不能计算 percentile。

## 16.3 只有 participants

不单独制造“排名”。

## 16.4 没有 rank / participants

读页面留空。

禁止：

`排名待补`

出现在正常阅读页面。

编辑页面可以继续使用输入框提示。

---

# 18. 需要统一“overall / subject ranking”的边界

综合：

`exam.overall.rankings`

单科：

`exam.subjects[key].rankings`

二者不能互相 fallback。

例如：

- 总体没有学校排名
- 但英语有学校排名

综合不能拿英语排名代替总体排名。

同样：

- 英语没有排名
- 总体有排名

单科不能拿总体排名代替英语排名。

这是非常重要的数据边界。

---

# 19. 同日考试与稳定排序

引入集中函数，例如：

`sortExamsChronologically(exams)`

规则：

1. date DESC
2. createdAt DESC
3. id ASC（最后稳定排序）

所有：

- 首页
- 时间轴
- 单科
- 分享
- API summary

统一使用。

不能让“编辑一次旧考试”改变最新考试的身份。

# 20. 数据结构策略

v0.12.0 首选：

- Schema 1 保持兼容
- 不做 KV 大迁移
- 允许增加可选运行字段，但不依赖它解决历史数据

如果实现阶段证明“未考”和“未记录”确实必须永久区分，再另开 schema 2 专项 PR，不和本次混在一起。

原因：

> 这次首先解决阅读真实性，不把数据模型一次性膨胀。

# 24. 验收标准

必须全部满足：

- 不存在“无理由默认语文”

# 28. 最终产品原则

本版本不是“增加几个比较模块”。

真正要建立的是：

> **用户选择什么，系统就看什么；系统显示什么，必须来自同一事实；没有数据就留空；不能比较就明确说不能比较；最近一次就是最近一次，不擅自替换。**

最终阅读模型：

`综合`
→ 最近一次整体坐标

`时间轴`
→ 每一次整体坐标

`单科`
→ 某一科的当前坐标 + 最近可比变化 + 完整历史

`考试详情`
→ 该场考试真实记录

这是下一阶段 score 从“能记录成绩”走向“真正可信地解释成绩”的核心架构基线。
