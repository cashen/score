# 我的高三人类思考审查 v0.12.30

## 基线

- Base main: ea325c98ae7f461cb4419720387974cfebb395d7
- Current product version: 0.12.29.11
- New branch: feat/human-thinking-v01230
- Scope: 分享 + 填写成绩 + 成绩阅读路径
- 核心原则：学生、家长、教师只作为审查视角，不成为产品角色；不新增角色入口、角色模式、角色专属页面或数据模型。

## 目标

把系统已有的数据语义翻译成普通人可以直接理解的连续体验：

记录考试 → 保存 → 看这次成绩 → 看前后变化 → 看单科历史 → 看时间轴 → 创建分享 → 被分享者打开分享页。

每一步只回答用户当下最自然的问题，不要求用户理解“scope、mode、comparison metric、projection”等内部概念。

## P0 人类语义

1. 默认比较的主指标与页面主值必须一致。当前单科页面先展示分数，但默认比较层可能优先学校相对位置；本版本改为“有分数就先比较分数，没有分数再按学校排名、班级排名回退”，并保留用户手动选择学校/班级排名。
2. 单场 live 分享必须明确为“这场考试会随记录更新，但不会因为以后新增考试而自动增加”。只有 trajectory + live 才说明“以后新增考试也会显示”。
3. snapshot 明确是“创建时固定的内容”，与 live 单场更新语义分开。
4. 成绩填写完成后，不再只提示“考试已保存”；保存成功的反馈需要告诉用户本次已记录多少科、总分是否为学校公布值、排名是否已有，并给出合理的下一步。
5. “完整”不再被语言层简单理解成“官方总分也已经发布”。六科齐全但学校总分尚未拿到，应显示为“六科已记全，学校公布总分待补”，避免用户误以为缺数据或不能继续。
6. 分享页面、私有页面、考试详情、时间轴使用同一套事实语义：总分、六科、学校排名、班级排名、比较依据不能互相错位。
7. 空白数据要与“未分享”分开。被分享者看到的“未分享”代表权限选择；私有端的“— / 待补”代表尚未记录，不混用。

## 页面检查

### 填写

- 成绩单到手后，用户能按真实顺序录入。
- 不知道的数据可以留空，但保存后系统必须告诉用户剩下什么。
- 重新打开未完整考试，优先落到还需要补充的科目。
- 保存以后不丢失原来的页面上下文。

### 成绩首页

- 第一眼明确“哪次考试、哪天、总分是什么状态、学校/班级位置是否已有”。
- 缺科、待补总分、缺排名不能全部压成一个“未完成”。
- “下一步”只有一个主动作：继续补这场，或记录下一场。

### 单科

- “这次分数”与“和上一场比”必须使用同一指标。
- 当前科目没有成绩时，不制造变化结论。
- 历次列表说明“最近一次有记录的成绩”，不暗示没记录就是零分。

### 总成绩 / 时间轴

- 每一场考试拥有自己的日期、类型、总分与排名上下文。
- 总成绩历史只展示总成绩语义；单科排名不混进总成绩。
- 点击一场考试，详情中的“以前”必须是这场考试时间之前、且可比较的考试。

### 分享

- 创建前能预测“别人实际会看到什么”。
- “这一次考试”“历次成绩”是唯一的人类范围选择，不出现角色选择。
- live / snapshot 说明变化方式，而不是技术术语。
- 单场 live：只跟随这场考试记录更新；不会吸收未来考试。
- 历次 live：未来新增考试也进入同一个分享页。
- 分享页首屏同时回答：是谁、哪场、什么时候、总分/位置是什么、有没有前后变化。

- 不增加角色专属 dashboard。
- 不修改 KV schema。
- 不迁移既有分享链接。
- 优先修改现有 app.js、record-semantics-v120.js 与测试，保持既有模块架构。
- 所有新增文案必须符合 PRODUCT-LANGUAGE-CONTRACT，不暴露内部实现名词。

## 测试

必须覆盖：

1. 默认单科比较与当前主值一致：有分数时按分数；无分数时按可用排名回退。
2. 单场 live 分享文案不再声称未来考试会自动加入。
3. trajectory live 才显示未来考试会进入分享页。
4. snapshot 文案保持固定内容语义。
5. 六科已齐但官方总分为空时，首页/保存反馈明确为“六科已记全、学校公布总分待补”，而不是笼统未完成。
6. 单科缺数据不产生变化结论。
7. 总排名与单科排名边界继续保持。
8. 既有分享链接、单场选定考试、时间轴、公开分享与安全检查回归。
