# v0.9.0 可信记录与成长型分享计划

## 1. 产品结果

v0.9.0 不继续扩大视觉装饰，重点修复成绩语义、比较、草稿和分享范围，让学生与家长明确知道：数字是否完整、正在比较什么、分享以后会不会增加内容、保存失败后数据是否仍在。

产品原则：未填写不等于零分；部分小计不叫总分；指标不偷换；不同单位不直接排序；异常考试不自动进入趋势；旧分享不被扩大；学生可以解释也可以不解释。

## 2. 用户场景与人本目标

### 成绩分批到手

家长今天只知道数学，明天拿到六科，后天才知道校排名。系统允许逐步补录，并始终区分正式总分、完整六科合计、部分小计和待补。

### 学生与家长一起看变化

用户选择分数时只回答分数，选择学校排名时只回答学校位置。若相邻考试不可比，系统寻找更早的最近可比考试，并明确说明比较对象；找不到时保留历史但不下结论。

### 第一次成绩就分享成长轨迹

一场考试也能创建成长轨迹。创建前明确说明后续考试会自动进入并要求确认；单次分享、快照和既有链接保持原义。

### 保存失败和多设备编辑

草稿仅在服务器明确保存成功后清除。网络失败或 revision 冲突时，本机内容仍可恢复，不以“提交过”推断成功。

### 学生解释权

提供可选的“我想补充一句”和“下次想试一件事”，仅家庭内可见、默认不分享、不进行完成率或好坏评价。

## 3. 范围与非目标

本版修改成绩推导、轨迹比较、录入补录、草稿生命周期、分享创建/阅读和家庭内轻量复盘；保持原有 Apple/钢笔视觉语言，只为新状态补充必要样式。

本版不做高考预测、大学推荐、AI 学习处方、打卡游戏化、学生与家长隔离的私密消息、JSON 导入、KV 迁移、认证或角色重构，也不自动升级旧分享。

## 4. 数据与 API 设计

### 4.1 总分语义

建立共享纯函数 `examScoreSummary(exam)`：

| kind | 条件 | 展示 |
| --- | --- | --- |
| `official` | 学校总分已填 | 学校公布总分 |
| `calculated_complete` | 未填总分、六科完整 | 六科合计 |
| `calculated_partial` | 未填总分、仅部分科目 | 已录 n/6 科，小计 |
| `missing` | 无总分且无科目成绩 | 总分待补 |
| `absent` | 缺考 | 本场缺考 |

空科目合计必须为 `null`；真实零分仍合法。正式总分存在时优先显示；与六科合计不同只提示核对，不覆盖数据。部分小计不进入总成绩趋势。

不修改既有 KV 记录，语义由共享函数从 `overall.officialScore`、科目和状态推导。`overall.calculatedScore` 继续兼容读取，但页面和分享不再把不完整合计冒充总分。

### 4.2 可比性

共享比较函数返回当前考试、参考考试、指标、状态和理由。按时间向前寻找第一场同时满足以下条件的考试：状态正常或完整；类别一致；系列和范围不冲突；排名 scope/label/basis 一致。缺考、特殊情况和部分总分跳过但保留在时间轴。

分数、学校排名、班级排名分开计算和展示。百分点、名次、分数不放进同一数值排序；“值得回看的科目”按所选指标分别列出。

### 4.3 成长型分享

保留存储字段 `scope`、`mode`、`examId` 和现有 locator。新建成长轨迹允许只有一场考试，但请求必须带 `futureExamsAcknowledged: true`。服务端只对 `scope=trajectory && mode=live` 要求确认。

旧 `scope=single` 永远只展示绑定考试；旧 snapshot 永远冻结；旧 grant 不迁移。响应增加可推导的 `examCount` 和 `includesFutureExams`，不写入新的 KV 主键。

分享阅读必须区分“未分享”和“待补”：字段未获授权时显示未分享或直接省略，字段获授权但为空时显示待补。单次链接写“家庭只分享了这一场”，不能推断学生只有一场记录。

### 4.4 学生复盘

考试增加可选 `reflection.studentNote`、`reflection.nextTry`，各最多 500 字，沿用 schemaVersion 1 对可选字段的向后兼容。服务端规范化输入；家庭读取可见；`publicProjection` 永不输出 reflection。旧记录无字段时等同为空。

### 4.5 草稿成功契约

移除基于 submit 时间的清理推断。考试 API 成功后由应用触发 `score:save-succeeded`，携带精确草稿 key/考试身份；draft 模块收到成功事件后才删除。API 失败、超时或 revision 冲突均保留草稿。

## 5. 页面行为

### 首页

- 无考试：主行动“记录第一次考试”。
- 最新考试不完整：主行动“继续补充这次考试”，显示已录科目和缺失科目。
- 最新考试完整：主行动“记录下一次考试”。
- 仅查看成员不显示编辑行动。
- 总分名称随实际来源变化，不再统一写成总分。

### 单科与轨迹

- 指标选择决定主结论和详情。
- 显示“与哪一场比较”及口径理由。
- 不可比的中间考试不阻断继续寻找更早参考。
- 缺考/特殊/待补节点仍在时间轴，并标明不进入趋势。

### 录入与补录

- 补录直接打开第一处缺失步骤。
- 草稿文案区分“保存在本机，尚未提交”“正在保存服务器”“考试已保存”。
- 最后步骤使用“检查并保存”，不同时出现两个含义相近的完成按钮。
- revision 冲突说明服务器已有更新，同时保留本机草稿。

### 分享设置

主选项改为“分享这一次考试”“分享当前快照”“分享成长轨迹”。实时摘要列出当前考试数、以后是否增加、包含/不包含字段和失效日期。一场考试选择成长轨迹时显示并要求勾选未来考试确认。

### 分享阅读

保留 v0.8.1 钢笔风格。补充分享范围、当前展示场数、分数模式和必要的跨年日期；明确未分享/待补；身份字段未授权时不泄漏也不暗示。

## 6. 分阶段执行与提交

### S0 基线、计划、分支、PR、checkpoint

验收：基于实时 main；旧工作区不被覆盖；计划与 PR 描述完整；checkpoint 能在断网后定位首个未完成阶段。

### S1 可信成绩语义

实现共享总分/完整度推导，修复空成绩为 0 和部分小计冒充总分，接入家庭页与分享页。

验收：0/1/5/6 科、正式总分、真实 0 分、赋分、缺考和正式/合计不一致全部有明确结果；不迁移旧数据。

### S2 可信比较

实现指标一致、最近可比考试搜索、状态排除和同单位科目展示。

验收：分数下降但排名上升时不偷换结论；可跨过不可比中间考试；缺考/特殊/部分记录不进入错误趋势。

### S3 补录与草稿

实现动态主行动、缺失步骤定位、明确保存状态和成功事件清理。

验收：保存失败/超时/CSRF/revision 冲突后草稿仍可恢复；成功只清除当前草稿；多家庭/学生/成员/考试隔离。

### S4 第一次成长分享

允许一场创建 live trajectory，增加未来考试确认和真实摘要，保持旧分享原义。

验收：一场创建后新增第二场会进入原链接；单次 live 仍绑定原场；snapshot 不变；撤销/过期/白名单正常。

### S5 家庭内学生复盘与页面整合

增加两个可选字段、家庭展示和分享排除；补齐移动端、键盘、减少动效/透明度和高对比度。

验收：可空、可中断、不评价；viewer 只读；任何分享 API 均不出现复盘字段。

### S6 版本、全量门禁、合并和生产

统一更新 package、lock、Worker 健康版本、README、CHANGELOG 和契约文档至 0.9.0。执行本地和 PR CI；截图复核后用 GitHub 实际 head SHA 合并；验证 main CI、部署、生产健康与资源。

## 7. 测试方案

- 单元：总分五种状态、完整度、可比搜索、指标变化、输入规范化。
- API/Schema：旧记录兼容、revision、KV 读写、认证/CSRF、删除恢复、分享撤销和过期。
- 草稿浏览器：成功清除；API 500、超时、冲突保留；多身份 key 隔离。
- 分享集成：single live、single snapshot、trajectory live 从一场增长到两场、trajectory snapshot、旧 grant。
- 隐私：notes、reflection、账户、家庭成员和安全字段不得进入公开投影。
- 浏览器：Chromium 360/390/768/1280 与 WebKit 390；软键盘下保存可达、键盘焦点、返回位置、三类分享预览、单/多/空记录。
- 显示偏好：reduced-motion、reduced-transparency、prefers-contrast。
- 本地最低门禁：`npm ci`、`npm run verify`、浏览器套件。

## 8. 风险与回滚

- 总分显示变化：不改数据，只切换共享推导；可单独回滚渲染。
- 分享范围扩大：只允许新建且明确确认；旧 grant 不变；可关闭新入口。
- 草稿残留：宁可保留也不误删；精确 key 清理。
- 比较结论减少：可信的“不足以比较”优先于不可信方向。
- 复盘误分享：白名单代码与测试双重阻断。
- 无 Schema/KV 迁移；出现生产问题通过新回滚 PR 恢复应用提交，不改用户数据。

## 9. 合并与生产门禁

PR head 与目标提交必须一致；verify 与浏览器 CI 均通过；截图人工复核；重新读取 main 和 expected_head 后合并。合并后 main CI、Cloudflare 部署必须成功，生产 `/api/health` 必须返回 appVersion 0.9.0、buildSha 等于合并 SHA、schemaVersion 1、storage workers-kv。首页、分享入口和递归 CSS/JS 资源逐字节匹配。最终 checkpoint 单独归档，避免事后文档改变已部署 main SHA。

## 10. 完成定义

学生和家长不会把未填写看成零分、部分小计看成总分、排名变化看成分数变化；保存失败不会丢草稿；一场考试可以在明确授权后成为持续成长轨迹的起点；学生复盘留在家庭内；旧记录、旧分享、KV、认证和 Schema 保持兼容。
