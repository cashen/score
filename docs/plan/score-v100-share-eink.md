# v0.10.0 E-ink 成绩阅读报告统一计划

## 目标与范围

本版本只重构外部分享页，把现有“总成绩 / 单科 / 时间轴”三种事实视图整理成像电子书一样安静、可连续阅读的成绩报告。视觉灵感来自 E-ink 阅读器：暖灰纸面、低饱和墨色、细规则线、充足留白、单列阅读，不引入终端霓虹、阴影、渐变、玻璃效果或游戏化徽章。

用户场景是学生把成绩分享给家长、老师或同学查看。学生需要看见事实而不是被排名刺激；家长需要快速回答“这次考了什么、各科怎样、与之前怎样、哪些信息没有分享”。因此页面必须明确当前记录、比较口径、时间顺序和分享边界，不能用一次成绩推断趋势。

范围仅限分享页的 CSS、必要的现有分享渲染标记和版本文档/测试。保留现有 KV、认证、分享白名单、快照/持续更新语义、比较算法、API 和 Schema；不增加 KV key、不迁移数据、不改变旧分享链接。

## 信息架构与状态契约

分享页固定提供三个等宽入口：`总成绩`、`单科`、`时间轴`。

* 总成绩：学生与分享模式 → 最新考试日期/类型 → 总成绩或诚实状态（缺考、部分科目小计、待补、未分享）→ 总体排名 → 单科六科 → 时间轴入口。
* 单科：科目选择器 → 每次考试的日期、分数/满分、校/班排名；分数、排名分别遵守白名单；未分享与待补不能混为一谈。
* 时间轴：按考试日期展示全部已分享考试，包含缺考、部分录入和特殊类型；每个节点可展开查看本场所有已分享字段（总分、排名、六科、满分、日期、类型），不凭空补值。

分享状态矩阵保持现有后端语义：单场持续更新、单场快照、持续轨迹单场（明确提示需下一场才可比较）、持续轨迹多场、轨迹快照；撤销/过期/未授权字段显示安全边界文案或省略。授权但为空显示“待补”，未授权显示“未分享”。

## 分阶段执行

### S0：接管、计划和 PR

1. 读取最新 checkpoint、GitHub `main`、开放 PR、Actions 与生产健康；确认基线 SHA。
2. 从最新 `main` 创建 `feat/score-v100-share-eink`，保留旧工作区修改。
3. 将本计划写入 `docs/plan/score-v100-share-eink.md`，创建草稿 PR，PR 描述完整复制目标、阶段、验收、风险和测试。
4. 初始化 `.codex/progress/score-v100-share-eink.json`，每个阶段结束写入命令、提交 SHA、CI/生产证据。

验收：分支父提交等于实时 `main`；PR 目标为 `main`；计划和 checkpoint 已可在分支读取。

### S1：E-ink 视觉基础层

1. 新增 `public/ui-v100-share-eink.css`，所有选择器限定在 `.share-ink-root` / `.ink-share`，避免污染登录和家庭内部页面。
2. 定义并使用暖灰纸面 `#F1F0EA`、纸张 `#FAF9F4`、正文 `#242525`、次级 `#6E716F`、规则线 `#C9C9C2`、强线 `#858781`、缺失 `#8D867A`、特殊状态 `#6E6868`。
3. 正文使用可用的中文无衬线字体；仅日期、分数、排名等数据使用等宽数字；不使用大面积深色、鲜红错误、阴影、渐变、毛玻璃。
4. 保留现有 `ui-v081-share-ink.css` 作为兼容基础，新层按加载顺序覆盖；新增资源必须进入首页资源完整性校验。

验收：分享页单列阅读节奏稳定；非分享页视觉不变；CSS 无 neon/terminal 颜色、阴影和渐变；资源引用为同源绝对路径。

### S2：总成绩阅读页

1. 保留现有总成绩数据和可信成绩语义，只调整标题层级、元信息、规则线和数据密度。
2. 把“当前考试事实”放在首屏，六科按固定顺序阅读；排名与分数分组，不制造综合结论。
3. 一次记录显示基线提示；部分成绩、缺考、待补、未分享使用不同文案和色彩变量。
4. 继续提供清晰的时间轴入口，不增加新的主行动或营销提示。

验收：六科、总分状态、排名、日期/类型和分享模式在 360px 宽度无需横向滚动；一次记录不会出现“上升/下降”结论。

### S3：单科与时间轴

1. 单科页采用可扫描的行式目录：考试名/日期/类型、分数与满分、排名分开对齐；科目切换控件触控区域不少于 44px。
2. 时间轴按日期稳定排序，最新节点可辨识但不使用强烈徽章；所有节点可键盘聚焦并打开详情。
3. 详情采用原生 `details/summary` 或等价可访问展开方式，列出本场所有白名单字段；空值、未授权和缺考保持语义差异。
4. 保持旧 URL 参数 `view=total|subject|timeline` 与 `subject`、`exam` 深链兼容。

验收：一场、两场、多场、快照和持续更新数据均能打开三视图；时间轴节点能展开全部已分享信息；旧链接不 404。

### S4：分享边界与回归审计

1. 对总分、总排名、单科分数、单科排名、反思/备注分别验证白名单投影；外部页不泄露私有字段。
2. 验证持续更新新增考试、快照固定内容、撤销、过期、未授权和授权空值。
3. 验证 API/Schema、KV 读写、比较口径、草稿保存/恢复、删除撤销不因前端改动回归。

验收：契约测试覆盖所有分享状态；生产候选构建的资源递归校验通过。

### S5：移动端、键盘和偏好

1. 在 360/390/768/1280px 检查间距、长中文、分数和排名不溢出；最小触控目标 44px。
2. 用键盘完成三视图切换、科目切换、时间轴展开；焦点指示清楚且不依赖颜色。
3. `prefers-reduced-motion`、`prefers-reduced-transparency`、`prefers-contrast: more` 下取消装饰纹理、过渡和低对比色。
4. 保持 200% 缩放可读，语义标题、导航、当前页和展开状态正确。

验收：Chromium 与 WebKit 浏览器场景通过；偏好媒体查询和可访问性契约通过。

### S6：测试与视觉验收

1. `npm ci` 后执行 `npm run verify`，包括现有单元/API/KV/分享白名单/比较/草稿/撤销契约。
2. 增加 v0.10 CSS/资源/标记契约测试，覆盖色彩 token、三视图、旧深链、隐私边界。
3. 运行浏览器场景（Chromium + WebKit）和生产构建资源完整性检查；记录视口和偏好矩阵。
4. 对一场与多场数据各做一次人工阅读复核：信息先于装饰、没有虚假确定性、时间轴详情完整。

验收：本地 verify 全绿；PR 专属 CI 全绿；截图/浏览器检查无横向滚动、遮挡或未标注字段。

### S7：版本、合并与生产验证

1. 将 `package.json`、`package-lock.json`、`wrangler.toml` 健康版本、CHANGELOG 和相关文档统一更新到 `0.10.0`；Schema 继续为 1。
2. 更新 checkpoint，提交可追踪 commit；PR 描述同步最终测试和风险。
3. 仅在 PR 分支 head 与 GitHub 实际 `expected_head` 一致且专属 CI 成功后合并。
4. 合并后重新读取 `main` SHA，等待主线 CI 与部署成功。
5. 访问 `/api/health`，必须返回 `appVersion: "0.10.0"`、`buildSha` 等于合并 SHA、`schemaVersion: 1`、`storage: "workers-kv"`；检查首页和分享页 CSS/JS 资源引用。
6. 最后写入完成 checkpoint；若部署或网络失败，保存失败命令、SHA 和下一步，恢复后先重读实时状态。

验收：PR 已合并；主线 CI、部署、健康检查、资源完整性均有可复核证据。

## 风险、回滚与不做事项

* 风险：CSS 覆盖内部页面、低对比度、窄屏溢出、详情隐藏字段、版本契约遗漏。通过根选择器、对比度断点、视口测试、白名单测试和版本搜索规避。
* 回滚：删除/回退 v0.10 CSS 与分享标记即可恢复 v0.8.1/v0.9 的渲染；无数据迁移，KV、认证、API 和旧链接无需回滚。
* 不做：不重写比较算法、不改变分享授权、不新增图表/动画/徽章、不把一次成绩包装成趋势、不把预览图中的示例数字写入产品。

## PR 合并门禁

PR 分支必须与目标 commit SHA 对齐；PR 专属 CI 通过；使用 GitHub 实际 `expected_head` 合并。合并后必须重新确认 `main` SHA、主线 CI、部署、生产健康版本和 buildSha、首页生产资源引用。任何未知、超时或网络错误均记为未验证，不得声称完成。
