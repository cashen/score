# v0.9.3 分享页长图计划

## 用户场景与人本目标

家庭成员在 Windows 上把成绩分享给家人时，需要看到的是“分享页本身”的完整信息，而不是一张只有一行分数的摘要卡。公开分享页仍应保持安静，不把图片导出入口塞给访客；管理端需要一个明确、可撤销、可再次尝试的“生成完整分享页图”动作。

## 影响范围

- 数据/API：继续复用现有分享白名单和预览 API，不改 KV、认证或 Schema。
- UI：公开分享页移除图片下载入口；管理端保留图片操作并明确为完整长图。
- 图片：SVG/PNG 输出包含总成绩、单科成绩、考试时间轴、标签与白名单提示，统一结构避免 Windows 下日期和提示重叠。
- 版本：升至 0.9.3，同步 package、lock、Wrangler 健康版本和变更记录。

## 分阶段任务与验收

1. 基线：以最新 main `b46484f` 建分支，记录 checkpoint 和实时 CI/生产事实。
2. 结构：重写分享图布局为纵向长页，固定行高、分区间距和可换行文本；验收 SVG 包含三大信息区且不含家庭备注。
3. 入口：公开页移除图片按钮和说明；管理端保留复制、打开和生成完整分享页图；验收移动端触控区域与键盘焦点不回退。
4. 验证：运行 `npm ci`、`npm run verify`，覆盖链接复制、白名单、预览 API、图片结构和版本契约。
5. 交付：创建 PR，确认专属 CI 通过后按 exact head 合并，验证 main CI、部署、生产 `/api/health` 与首页资源。

## 风险、回滚与测试

主要风险是长图过长、字体缺失或浏览器 Canvas 导出失败。SVG 作为可访问预览回退，固定最大高度并保留网页完整轨迹；若生产出现回归，可直接回滚本次单一版本提交，KV 数据无需迁移。测试包含单元/API 回归、分享白名单、复制/打开、SVG 内容合同、移动布局、键盘可访问性和生产构建资源检查。
