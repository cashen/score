## Product problem
The visible issue is not simply left alignment. A centered outer shell can still leave the actual information column pinned to the shell edge. This creates asymmetric visual weight and an unstable reading axis. The product needs one spatial system: centered work/reading areas, left-aligned information inside them, larger peripheral whitespace on large displays, and controlled reflow on tablets/mobile.

## Architectural principles
1. Center the container, not every line of text.
2. Large displays increase outer whitespace instead of stretching the reading measure.
3. One canonical layout scale owns width, gutter and reading measure.
4. Responsive behavior is reflow, not desktop scaling.
5. Reading pages and editing pages use different density rules while sharing the same spatial vocabulary.
6. UI changes remain presentation-only: no Schema 1, Workers KV, API, Share v2, permission or comparison semantics changes.

## Canonical spatial scale
- Outer shell: 1200px
- Workspace: 960px
- Reading frame: 760px
- Narrow measure: 640px
- Outer gutter: clamp(16px, 3vw, 32px)
- Section rhythm: clamp(28px, 5vw, 48px)

## Implementation stages
### 1. Layout foundation
- Add canonical layout tokens to the existing UI Foundation.
- Rebind topbar/container/private app workspace/home page to the shared scale.
- Rebind reading sections and public shells to stable centered frames.
- Keep inner copy left-aligned unless a control has a clear reason to be centered.

### 2. E-ink share
- Keep v0.14.3 E-ink visuals.
- Center the E-ink shell and use a narrower inner reading measure on desktop/tablet.
- At <=760px, let the inner measure fill the shell.
- Preserve 44px controls, focus, reduced-motion, high-contrast and forced-colors support.
- Preserve total/subject/timeline URLs, share-field semantics and historical facts.

### 3. Private home/navigation
- Recheck navigation → current exam → current score → recent change → subjects → history → next action as one visual axis.
- Eliminate width divergence between app-main/home-page/app-main-tabs.
- Keep the action hierarchy calm and avoid dashboard-style state colors.

### 4. Exam entry/edit
- Preserve progressive subject selection and existing save/failure behavior.
- Use the sequence exam information → subjects actually taken → score → position/context → save.
- Ensure narrow/mobile editing stays in the same task context.

### 5. Sharing management
- Structure by human task: what to share → what others will see → how it updates → existing shares.
- Keep advanced options available without overwhelming the main task.

### 6. Family/settings/onboarding
- Apply the same workspace/readability rules without creating an administrative dashboard feel.
- Keep empty states low-pressure and explicit about the next useful action.

### 7. CSS ownership cleanup
- Do not add another general-purpose styling layer.
- UI Foundation owns global spatial/typographic primitives.
- Component CSS owns local behavior.
- E-ink owns only share-specific visual treatment.
- Retire redundant selectors only after browser verification proves they are unused.
