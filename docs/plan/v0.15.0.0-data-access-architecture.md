# v0.15.0.0 — Score Data Access Architecture

## Goal
Complete the next architectural boundary after v0.14.5.0: canonical exam indexes, bounded Bulk Get reads, serialized index writes, active/trash separation, and a dedicated public-share browser entry.

## P0
- Normal exam reads use `exam-index:{studentId}` and Workers KV Bulk Get.
- New writes stop maintaining `exam-summary:{studentId}:{examId}` duplicates.
- Pre-v0.15 installations may perform one bounded compatibility migration when the canonical index is absent.
- `StudentIndexCoordinator` serializes per-student exam index mutations.
- Active exams and deleted exams use separate indexes.
- Save UI consumes the server response and keeps the exam editor open.
- Public share routes load `share-app.js`, not the private application bundle.

## Invariants
Schema 1, Share v2, permissions, score/comparison semantics, existing URLs, and deleted-record privacy semantics remain unchanged.
